#네트워크 #오키야토시야

## 1장
- 유선랜
	- 이더넷 : OSI 1~2계층
- 무선랜
	- IEEE 802.11 시리즈
- 스위치
	- L2 : 유선 랜을 묶는 것
	- L3 : 네트워크와 네트워크를 연결하는 기능 (라우팅이 가능함)
	- L4 (TCP로 배분 가능) 또는 L7 (APP 레벨에서 배분 가능): 부하 분산 및 애플리케이션에 맞게 통신을 제어할 수 있는 고급 스위치
- 무선 액세스 포인트 (무선 랜 라우터)
	- 무선 랜을 묶는 것 
- ONU
	- 광 회선과 공유기를 연결하고 광 신호와 디지털 신호를 변환하는 장치
- 라우터
	- 네트워크와 네트워크를 연결하는 기능이 있는 네트워크 장비
	- 라우터와 L3 스위치의 차이점은?
- 가상 라우터
	- VPC (Virtual Private Cloud) : 퍼블릭 클라우드를 가상 프라이빗 클라우드로 이용하는 기술 = 가상 데이터 센터
	- VPC 쪽 연결점이 가상 라우터
		- 라우터는 전용 하드웨어로 제공
		- 가상 라우터는 클라우드에서 실행되는 소프트웨어로 제공
- 인터네트워킹
	- 복수 네트워크를 서로 연결하는 것
	- 장점 
		- 불필요한 통신을 네트워크 전체로 확산시키지 않는다
		- 고장이 나도 영향이 광범위하게 퍼지는 것을 막을 수 있다
		- 개별 네트워크를 각 조직의 방침에 따라 관리할 수 있다
- 조직(AS)
	- Autonomous System (자율 시스템)
	- 인터넷을 구성하는 단위 = 어느 하나의 관리 주체로 보유 및 운용되는 독립된 네트워크
- tracert : 실행한 PC => 목적지 PC 가는 네트워크 IP 주소 검색 
	- unix : traceroute 
- 프로토콜
	- 통신하기 위한 공통된 약속
	- TCP/IP가 주류

## 2장
- TCP/IP
	- 인터넷 프로토콜 스위트 = 다른 컴퓨터 벤더나 운영체제, 서로 다른 회선끼리 통신할 수 있게 하는 통신 프로토콜 세트
	- Transmission Control Protocol / Internet Protocol

| 4   | 응용 계층      | HTTP, DNS 등         | 애플리케이션에 맞추어서 통신한다.                        |
| --- | ---------- | ------------------- | ----------------------------------------- |
| 3   | 전송 계층      | TCP, UDP            | IP와 애플리케이션을 중개해서 송신된 데이터를 확실하게 전ㄷ라한다.     |
| 2   | 인터넷 계층     | IP, ICMP, ARP 등     | 네트워크 주소를 기반으로 수신 측 컴퓨터까지 데이터를 전송한다.       |
| 1   | 네트워크 접근 계층 | 이더넷, 무선 랜(Wi-Fi) 등0 | 컴퓨터를 물리적으로 네트워크에 연결해서 기기 간에 전송할 수 있게 한다.  |
- IP 주소
	- Private IP 주소 : 랜 내부에서 사용되는 주소
	- Global IP 주소 : 인터넷에서 사용되는 주소
- MAC 주소
	- 이더넷에서는 하드웨어끼리 통신 상대를 특정하고자 MAC 주소를 사용
	- TCP/IP에서는 통신 상대를 특정하고자 IP 주소를 사용
- ARP 주소
	- Address Resolution Protocol
	- 같은 네트워크에 속한 컴퓨터끼리 통신할 때는 우선 IP 패킷을 보내고 싶은 상대의 MAC 주소를 조사하고, 그 MAC 주소로 패킷을 보내는 흐름.
	- IP주소에 대응하는 MAC 주소를 알아내기 위해 네트워크 전체에 패킷을 보냄 (ARP Request)
	- 자신을 찾는 것을 안 컴퓨터가 응답함 (ARP Reply)
- 다른 네트워크와의 통신
	- 라우터(또는 L3 스위치)가 필요함
	- 다른 네트워크의 IP 주소와 통신할 때, 미리 지정된 기본 게이트웨이 IP 주소로 통신을 보낸다. 
- 패킷
	- 통신할 때 데이터를 교환하는 방법
		1. 회선 교환 : ex) 전화기. 데이터를 교환하는 동안 계속해서 회선을 점유하는 방식
		2. 패킷 교환 : 주고받는 데이터를 '패킷' 이라는 작은 덩어리로 나누고, 회선을 공용해서 복수의 통신을 내보내는 방식
	1. 운송 정보 = 헤더
	2. 화물 = 페이로드
 - IP 주소 분석
	 - DHCP : 라우터에서 IP 주소를 자동으로 할당받는 기술
		 - Dynamic Host Configuration Protocol
		 - DHCP Discover : Client => Server : DHCP 서버 찾으려고 함
		 - DHCP Offer : Server => Client : 클라이언트에게 설정을 제안하는 통신을 보냄
		 - DHCP Request : Client => Server : 제안된 설정의 세부사항을 요청함.
		 - DHCP ACK : 설정의 세부사항을 지정하는 통신을 함
	 - 서브넷 마스크
		 - IP주소는 네트워크 + 호스트 구성 
		 - 192.168.1 (네트워크) + .1 (호스트)
		 - ex) S/M : 255.255.255.0
		 - 네트워크 주소 : 192.168.1.0
		 - 브로드캐스트 주소 : 192.168.1.255
		 - CIDR 표기법 : 192.168.1.0/24 (네트워크부 24개 bit)
		 - A클래스(/8), B클래스(/16), C클래스(/24)
- 네트워크 장비
	- L2 스위치 : MAC 주소에 따라 데이터를 전송하는 것
	- L3 스위치 (& 라우터) : L2 스위치 + 다른 네트워크를 연결하는 기능
		- 주로 이더넷을 지원하는 WAN 회선을 수용함
	- 라우터 : 전화 회선, 이더넷이 아닌 광 회선도 수용 가능
		- 보안 측면에서 강함
			- 패킷 필터 : 허용할 통신과 차단할 통신을 설정 (L3 스위치도 있음)
			- 패킷 체크 ; 송수신의 일관성 검사나 위조 방지 (라우터가 더 뛰어남)
			- 추가로, 방화벽, UTM 도 있음
	- L4, L7 스위치 : 로드 밸런서
		- 시스템에 대한 요청을 여러 서버에 분산해서 통신량의 균형을 조절함
		- L4 스위치 : TCP 헤더 등 프로토콜 헤더의 내용을 해석하고 지정된 알고리즘에 근거하여 데이터를 분산해서 전송한다. 
			- 주요 배분 방식 
				- 라운드로빈(Round robin) : 순서대로 할당
				- 최소 연결(least connection) : 가장 커넥션이 적은 곳으로 데이터를 분산함
		- L7 스위치 : L4 스위치에 더해서 응용 계층의 내용까지 분석하여 데이터를 분산해서 전송함 
			- 특정 사용자-서버의 연결 (세션)을 유지하는 기능을 실현함.
- TCP와 UDP
	- 신뢰성 => TCP
	- 속도 => UDP 
	- 포트번호 : 통신하는 대상 컴퓨터의 애플리케이션을 특정하는 번호 
			- 0~1023 : well-known port
			- 80 http / 443 https / 110 pop3 / 25 smtp / 22 ssh / 53 dns (udp) / 123 ntp
			- 동적포트번호 (49152~65535) : 출발지 접속 포트 번호
- ICMP
	- Internet Control Message Protocol
	- TCP/IP가 구현된 컴퓨터 및 네트워크 기기 사이에서 통신 상태를 확인
	- IP 계층에서 동작하지만, IP 위에서 동작하는 프로토콜
	- ping, tracert
	- TCP, UDP 없이 동작하므로 포트 번호 없음. 
- NAT
	- Network Address Translation
	- 라우터가 private IP주소를 global IP 주소로 변환하는 기술 (반대도 포함)
	- netstat
- Private IP 주소
	- 클래스 A : 10.0.0.0/8
	- 클래스 B : 172.16.0.0/12 => /16, /24 로도 분할
	- 클래스 C : 192.168.0.0/16 => /24 로도 분할
- CIDR
	- Classless Inter-Domain Routing
	- 목적지 여러 개를 모은 것
- 라우팅
	- 라우팅 테이블 : 네트워크로의 통신을 어떤 라우터로 전달할 지 기록함
	- 정적 라우팅
		- 라우팅 테이블을 수동으로 관리하는 기술
	- 동적 라우팅
		- 라이팅 테이블을 자동으로 관리하는 기술
		- 라우팅 프로토콜 

## 3장
- HTTPS
	- SSL/TLS 구조로 구현됨
	- SSL : Secure Sockets Layer / TLS : Transport Layer Security
- SSL 인증서
	- 인증기관 (CA, Certification Authority) 이라는 신뢰할 수 있는 제삼자 기관이 이용자(도메인 소유자)에게 발행하는 것
	- 역할
		1. 데이터 암호화 : SSL 인증서에 포함되는 공개 키를 사용하여 암호화 통신을 위한 비밀 키를 안전하게 교환할 수 있고, 암호화 통신을 실현할 수 있음.
		2. 도메인 소유 증명 : SSL 인증서로 해당 도메인은 A가 소유하는 도메인이라는 것을 제삼자인 인증 기관에서 보증한다.
		3. 데이터 변조 방지 : 제삼자 기관이 보증하는 인증서로 암호화된 통신은 변조되지 않고 확실하게 A의 정보임을 보증한다. 
	- 인증 기관 신뢰
		- 인증 기관 운용 규정 (CPS, Certificate Practice Statement) 문서를 공개하여 보안 정책을 규정하고, 본사를 둔 국가의 정부 등이 이 문서를 인증함으로써 우리는 인증 기관을 신뢰할 수 있습니다. 
	- 종류
		- 도메인 인증 (DV, Domain Validation)
			- 조직의 실재성 확인 X
			- 주로 개인, 법인
			- 와일드카드 인증서 대응 O
				- 와일드카드 : 같은 도메인에 속한 복수의 서브 도메인까지 한 번에 보호하는 형태의 인증서임.
			- 가격 가장 저렴함, 개인정보 다루지 않는 웹사이트
		- 기업 인증 (OV, Organization Validation)
			- 와일드카드 인증서 대응 O
			- 중간 가격, 개인 정보 입력이 필요한 회원제 사이트
		- EV 인증 (EV, Extended Validation)
			- 와일드카드 인증서 대응 X
			- 비싼 가격, 기업 사이트 / 온라인 뱅킹
- URL, DNS
	- URL : Uniform Resource Locator
		- ex) http://93.184.216.34/news/index.html
	- DNS : Domain Name System
		- 웹사이트 주소 <=> IP주소 대응
		- 인터넷상의 거대한 분산 데이터베이스
		- 콘텐츠 DNS 서버 + 캐시 DNS 서버로 구성됨
			- 콘텐츠 DNS 서버 : 각 도메인의 바탕이 되는 기본 정보를 가지고 있음 
			- 캐시 DNS 서버 : 클라이언트가 문의하면 콘텐츠 서버에 요청 & 응답받고 클라이언트로 다시 전달하는 중계 역할을 함.
	- 도메인 : 인터넷상 주소 
		- ICANN : 전 세계 단위
		- 레지스트리 : 도메인 관리 기관 
		- 레즈스트라 : 도메인 중개 등록 업체. 
		- 도메인 종류
			- gTLD : generic Top Level Domain
				- 레지스트리 : Verysign 등
				- 레지스트라 : 가비아, 예스닉, 후이즈 등
				- sTLS도 있음. sponsored Top Level Domain
			- ccTLD : country code Top Level Domain 
				- 국가 코드 최상위 도메인 
				- 레지스트리 : 한국인터넷진흥원(KISA)
				- 레지스트라 : 가비아, 아이네임즈, 후이즈 등
- HTTP
	- 웹 브라우저와 웹 서버 간의 상호 작용을 지원하는 프로토콜
	- 데이터를 요청하고 전송하는 상태 비저장 프로토콜 (상태에 대한 정보가 없음)
	- HTTP Request : GET(리소스 요청), POST (데이터 송신), PUT (파일 업로드)
	- HTTP Response : 상태코드 
- 쿠키와 세션
	- 쿠키 : 웹사이트를 열람한 사용자 정보를 클라이언트가 보관하고, 다음 액세스부터 그 정보를 클라이언트가 서버로 보내서, 사용자 식별을 할 수 있게함.
	- 세션 : 웹 사이트를 방문해서 수행하는 일련의 행동, 세션ID를 주고받으며 사용자 식별을 함. ID에 대응하는 세션 변수는 서버에서 관리함. 
- 인증 (Authentication)
	- 다중 인증 (MFA)
	- 위임 인증 => 사용되는 기술 : OAuth
- 메일 전송 프로토콜 (SMTP)
	- POP befor SMTP
	- SMTP Auth
- HTTP/2
	- SPDY 프로토콜로 구성됨
	- HTTP/1.1 : 동시에 복수의 요청을 보낼 수 있지만, '요청 하나에 응답 하나'라는 기본 구조 그대로. 
		- 웹페이지 1개 = 여러 개의 파일과 이미지 파일, 하나마다 GET 요청을 보내야 함. 
		- 접속 수 제한
		- 프로토콜이 텍스트 기반이라서 텍스트 파싱에 시간이 걸린다.
		- 파일을 가져올 때마다 거의 같은 HTTP 헤더를 송수신한다. 오버헤드.
	- HTTP/2 : index.html 가져온 후, 구성 파일에 대한 클라이언트 요청이나 서버 응답을 병렬로 한다. 
		- h2 : TLS로 암호화된 통신
		- h2c : 평문 통신
		- 주요 브라우저에서는 h2를 지원하고 h2c는 지원하지 않는다. 
		- **즉, h2가 사실상 필수 요건이므로, HTTP/2로 웹 컨텐츠를 전달하려면 SSL/TLS가 필수다.** 
- Ajax : 웹의 편의성을 높인 프로그래밍 기법. 에이젝스.
	- XMLHttpRequest : 이미 읽은 웹페이지에서 다시 HTTP 요청을 보내 웹페이지 전환 없이 데이터를 송수신할 수 있는 기능을 제공.
		- 비동기 통신을 구현할 수 있지만, 서버 측에서 푸시 통신을 하는 등 양방향 통신이 어려웠음
		=> WebSocket (웹소켓) 기술이 탄생함. 
- Web API
