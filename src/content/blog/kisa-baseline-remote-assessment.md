## 배경

교내 서버에는 인증서 자동 갱신을 위한 작은 에이전트(tracer)가 이미 설치돼 매주 포털에
보고하고 있습니다. 같은 경로로 **서버 보안 설정도 판정**할 수 있다면, 1년에 한 번 사람이 들어가서
보던 점검을 매주 자동으로 볼 수 있습니다.

기준은 KISA의 「2026 주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드」로 잡았습니다.

## 숫자로 보는 결과

| 구분 | Unix 서버 | 웹 서비스 | 합계 |
| --- | --- | --- | --- |
| 가이드 전체 항목 | 67 | 26 | **93** |
| 원격 판정 대상으로 선정 | 38 | 9 | **47** |
| └ 기존 수집 데이터로 즉시 판정 | | | 15 |
| └ 새 수집 항목 필요 | | | 32 |
| 제외 (사유 문서화) | 29 | 17 | **46** |

절반을 뺐다는 것이 핵심입니다. 그리고 **뺀 이유를 하나하나 남겼다**는 것이 더 중요합니다.

## 무엇을 빼는가

- **사람의 판단이 필요한 항목.** "불필요한 서비스가 있는가"는 그 서버의 용도를 알아야 답할 수 있습니다.
- **수집 자체가 위험한 항목.** 판정하려면 비밀값을 읽어야 하는 것들입니다. 예를 들어 SNMP
  community string이 기본값인지 보려면 그 값을 읽어 와야 합니다. 이런 항목은 **영구 제외**했습니다.
  점검 시스템이 비밀번호 저장소가 되는 순간, 점검 시스템이 가장 좋은 공격 대상이 됩니다.
- **이 환경에 해당하지 않는 항목.** 쓰지 않는 서비스에 대한 설정 점검입니다.

## 어떻게 수집하는가: 내용이 아니라 성질을

수집 방식을 다섯 가지로 정해, 항목마다 하나를 고르게 했습니다.

| 방식 | 의미 | 예 |
| --- | --- | --- |
| listener | 어떤 포트가 열려 있는가 | 불필요한 원격 서비스 포트 |
| probe | 직접 붙어 보면 어떻게 응답하는가 | 구형 TLS 프로토콜 허용 여부 |
| stat | 파일의 권한·소유자 | 주요 설정 파일 권한 |
| value | 특정 설정의 값 | SSH 루트 로그인 허용 여부 |
| count | 몇 개인가 | UID 0 계정 수, 빈 비밀번호 계정 수 |

원칙은 **"내용을 읽지 말고 성질을 보고하라"** 입니다. 계정 파일을 통째로 보내는 대신 조건에 맞는
계정의 **개수만** 보냅니다. 판정에는 그걸로 충분하고, 유출돼도 피해가 작습니다.

## 판정의 정직함

- **"미확인"을 "취약"에 더하지 않습니다.** 수집에 실패한 항목을 취약으로 세면 숫자는 커지지만
  보고서는 거짓말을 합니다. 반대로 양호로 세면 위험을 숨깁니다. 미확인은 미확인으로 따로 보고합니다.
- **자가 보고의 한계를 명시합니다.** 에이전트가 보내는 값은 그 서버가 침해되지 않았다는 전제에서만
  믿을 수 있습니다. 그래서 이 체계는 "설정 관리"이지 "침해 탐지"가 아니라고 보고서에 적어 둡니다.

## 조치는 이름으로만

판정 다음은 조치입니다. 여기서 가장 쉬운 설계는 포털이 서버에 명령 문자열을 내려보내는 것인데,
그러면 포털 하나가 뚫릴 때 **전체 서버가 함께 장악**됩니다. 그래서 포털은 에이전트가 이미 알고 있는
**조치의 이름**만 보낼 수 있게 했습니다. 실행할 수 있는 것의 목록은 서버 쪽 코드에 고정돼 있습니다.

사람 없이 도는 주간 실행에서는 서버를 잠글 수 있는 변경(방화벽, SSH 설정)을 하지 않습니다. 그런
변경은 담당자가 화면 앞에 있을 때, 미리보기 후, 되돌릴 수 있게만 합니다.

## 배운 것

가이드를 자동화하는 일은 항목을 코드로 옮기는 일이 아니었습니다. **어떤 항목을 자동화하면 안
되는지** 결정하는 일이었고, 그 결정의 이유를 남기는 일이었습니다.
